# nuwax-sqlparser 0.63.0 Changelog

This is the first release of the `nuwax-sqlparser` fork, derived from
upstream `sqlparser` 0.62.0. The fork exists to ship MySQL-specific
additions that have not yet been merged upstream.

**Package:**

- Renamed package from `sqlparser` to `nuwax-sqlparser`. The library
  name (`[lib] name = "sqlparser"`) is preserved, so downstream code
  can keep `use sqlparser::...` imports unchanged by depending on the
  crate via `sqlparser = { package = "nuwax-sqlparser", version = "0.63.0" }`.

**Implemented enhancements:**

- Added support for standalone MySQL `CREATE FULLTEXT INDEX` and
  `CREATE SPATIAL INDEX` statements. These previously failed with
  `Expected: an object type after CREATE, found: FULLTEXT` because
  `parse_create` had no dispatch branch for the `FULLTEXT` / `SPATIAL`
  prefix keywords.
- Added a new `FullTextOrSpatialKind` enum and a
  `CreateIndex::fulltext_or_spatial: Option<FullTextOrSpatialKind>`
  field to preserve the original keyword through the AST and the
  `Display` round-trip.
- Added `Parser::parse_create_fulltext_or_spatial_index` (parallel to
  `parse_create_index`) to parse the MySQL-only standalone grammar.

The in-table form (`CREATE TABLE t (... FULLTEXT INDEX ...)`) and
`ALTER TABLE ... ADD FULLTEXT INDEX (...)` were already supported by
upstream 0.62.0 and continue to work unchanged.
